Confidence: 0.85
- Treats a clean typecheck plus the custom "Impeccable" design detector as the definition of done: `npx tsc --noEmit` exiting 0 (reported as `TSC_EXIT=0`) and `node ~/.config/opencode/skills/impeccable/scripts/detect.mjs --json <changed files>` returning `[]`. Run both on the touched files and echo the results in the final report. Also *invokes the skill by name* when they want a design pass ("usá el skill /impeccable para mejorar X") — that means load the skill's references (polish, craft-floor) and its `context.mjs` design context first, then run `detect.mjs` over every touched file. Confidence: 0.85
- Runs multiple models/agents on the same project and passes state between them (checklists addressed to a named model, e.g. "Checklist para Qwen"). - Audits UI details personally — placement of controls (close/X belongs at the right edge of the action group), icon-button affordances, touch-target size (asks to bump small targets, e.g. 36px chips → 40px, 44px inputs → 46px, pill buttons ≥ 40px tall), disabled/no-op states — and asks for targeted corrections ("corregir algo y mejorar un botón") rather than rewrites; keep edits surgical to the named files. Confidence: 0.8
- Also audits mobile responsiveness down to the CSS property: reports a component that "se deforma y rompe el maquetado" on small screens and prescribes the fix literally (`max-width:100%`, `white-space:nowrap`, `overflow:hidden`, `text-overflow:ellipsis`, `flex-shrink:1`), plus the collision concern that matters — a long label must never grow wide enough to hit the neighbouring X/collapse control. Expect those named values to be honored (translated to the project's Tailwind/token equivalents) and verified at the stated breakpoint. For a bar that overflows on narrow screens they ultimately want it kept to a **single row** (truncate the label with ellipsis, controls right-aligned at the same height) — the earlier `flex-wrap`/two-row fallback under ~480px was rejected, along with the redundant section label ("Asistente") in that header. Confidence: 0.75
- Asks for a polish pass on one named control ("específicamente el ícono search que está al lado del asistente") but expects the same treatment applied consistently across the feature — the sibling inputs/selectors get aligned to the same design language, not just the element named. Confidence: 0.7

Confidence: 0.7
- Treats dead-code cleanup as part of any deletion task, stated explicitly: remove the JSX, the now-unused icon imports, and any handler wired only to the deleted elements; grep project-wide to confirm nothing else references them and delete components left orphaned; then prove it on the running dev server — fetch the page and grep the served HTML for the removed labels, expecting 0 occurrences and a 200 with no console errors. - No raw inline SVG icons in the UI: use the project's lucide icon set, and style inputs per the existing DESIGN.MD system (field fill at rest, border only as an ink focus ring, focus-reactive leading icon) reusing design tokens instead of one-off classes. Confidence: 0.7
